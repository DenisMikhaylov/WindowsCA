# Лабораторная работа: Резервное копирование и восстановление Windows CA

## 🎯 Цель работы
Получить практические навыки создания резервной копии центра сертификации (CA) и его последующего восстановления с использованием различных встроенных инструментов Windows Server. В ходе работы вы научитесь сохранять базу данных, закрытый ключ и параметры реестра CA, а затем восстанавливать их на том же или новом сервере.

## 📋 Требования к лабораторной среде
- **Windows Server** (2016/2019/2022) с установленной ролью **Active Directory Certificate Services (AD CS)** и настроенным центром сертификации (Enterprise или Standalone).
- Учетная запись с правами **администратора CA** (для Enterprise CA — член групп Domain Admins, Enterprise Admins или локальные администраторы; для Standalone CA — локальные администраторы).
- Доступ к локальному диску или сетевой папке для хранения резервных копий.
- (Опционально) Второй сервер с установленной ролью AD CS для проверки восстановления на другом узле.

## 📚 Теоретическая справка
Центр сертификации — критически важный компонент инфраструктуры открытых ключей (PKI). При его отказе или миграции необходимо восстановить три ключевых компонента:
1. **База данных CA** — содержит информацию о выданных и отозванных сертификатах.
2. **Закрытый ключ CA** — используется для подписи всех выдаваемых сертификатов и списков отзыва (CRL).
3. **Параметры реестра** — конфигурация CA, включая шаблоны сертификатов (для Enterprise CA) и другие настройки.

Для выполнения этих задач Microsoft предоставляет три основных инструмента:
- **Оснастка «Центр сертификации» (Certification Authority)** — графический интерфейс с мастерами резервного копирования и восстановления.
- **PowerShell** — командлеты `Backup-CARoleService` и `Restore-CARoleService`.
- **Certutil** — утилита командной строки с параметрами `-backupDB`, `-restoreDB`, `-backupKey` и `-restoreKey`.

## 🔬 Задание 1. Резервное копирование CA с помощью оснастки «Центр сертификации»

### Шаг 1.1. Запуск мастера резервного копирования
1. Войдите на сервер CA с учетной записью администратора CA.
2. Откройте **Server Manager** → **Tools** → **Certification Authority** (или запустите `certsrv.msc`).
3. В левой панели щелкните правой кнопкой мыши по узлу с именем вашего CA.
4. Выберите **All Tasks** → **Back Up CA…** (Все задачи → Резервное копирование CA).

### Шаг 1.2. Выбор компонентов для резервного копирования
1. На странице приветствия мастера нажмите **Next**.
2. На странице **Items to Back Up** (Элементы для резервного копирования) установите флажки:
   - **Private key and CA certificate** (Закрытый ключ и сертификат CA);
   - **Certificate database and certificate database log** (База данных сертификатов и журнал базы данных).
3. Укажите **папку** для сохранения резервной копии (например, `C:\CABackup`). Папка должна быть защищена от несанкционированного доступа.

### Шаг 1.3. Защита закрытого ключа паролем
1. На странице **Select Password** (Выбор пароля) введите надежный пароль для защиты закрытого ключа CA. Пароль потребуется при восстановлении.
2. Нажмите **Next** и затем **Finish** (Готово).

### Шаг 1.4. Проверка результатов резервного копирования
После завершения мастера проверьте указанную папку. В ней должны появиться:
- Файл **`<CA_Name>.p12`** — содержит сертификат CA и закрытый ключ, защищенный паролем.
- Папка **Database** — содержит файлы базы данных (`certbkxp.dat`, `edb###.log`, `<CA_Name>.edb`).

> ⚠️ **Важно:** После создания резервной копии остановите службу `certsvc` командой `net stop certsvc`, чтобы предотвратить выдачу новых сертификатов во время дальнейших операций (если вы планируете восстановление или миграцию).

## 🔬 Задание 2. Резервное копирование CA с помощью PowerShell

### Шаг 2.1. Запуск PowerShell от имени администратора
Откройте PowerShell с повышенными привилегиями (Run as Administrator).

### Шаг 2.2. Выполнение полного резервного копирования
Используйте командлет `Backup-CARoleService` с параметром `-Path`, указывающим папку назначения. Например:
```powershell
Backup-CARoleService -Path "C:\CABackup_PS"
```
Этот командлет создаст резервную копию базы данных и закрытого ключа.

### Шаг 2.3. Резервное копирование только ключа или только базы данных (опционально)
- Только закрытый ключ и сертификат:
  ```powershell
  Backup-CARoleService -Path "C:\CABackup_KeyOnly" -KeyOnly
  ```
- Только база данных:
  ```powershell
  Backup-CARoleService -Path "C:\CABackup_DbOnly" -DatabaseOnly
  ```
Эти параметры полезны, когда требуется раздельное хранение компонентов.

### Шаг 2.4. Защита паролем (рекомендуется)
Для шифрования закрытого ключа паролем используйте параметр `-Password`:
```powershell
Backup-CARoleService -Path "C:\CABackup_Secure" -Password (Read-Host -Prompt "Введите пароль" -AsSecureString)
```
Или с явным указанием пароля (для лабораторных целей):
```powershell
Backup-CARoleService -Path "C:\CABackup_Secure" -Password (ConvertTo-SecureString "P@ssw0rd!" -AsPlainText -Force)
```

## 🔬 Задание 3. Резервное копирование CA с помощью Certutil

### Шаг 3.1. Открытие командной строки от имени администратора
Запустите **Command Prompt** (cmd.exe) с правами администратора.

### Шаг 3.2. Резервное копирование базы данных
Выполните команду:
```cmd
certutil -backupDB C:\CABackup_CertUtil
```
Параметр `-backupDB` создает полную резервную копию базы данных Active Directory Certificate Services.

### Шаг 3.3. Резервное копирование закрытого ключа и сертификата
Выполните команду:
```cmd
certutil -backupKey C:\CABackup_CertUtil
```
Эта команда сохраняет сертификат CA и закрытый ключ в PFX-файл.

### Шаг 3.4. (Опционально) Защита ключа паролем
Добавьте параметр `-p` для указания пароля:
```cmd
certutil -backupKey C:\CABackup_CertUtil -p P@ssw0rd!
```

## 🔬 Задание 4. Восстановление CA с помощью оснастки «Центр сертификации»

> **Предварительное условие:** Роль AD CS должна быть установлена на целевом сервере (том же или новом). Служба `certsvc` должна быть остановлена перед восстановлением базы данных, если она была запущена.

### Шаг 4.1. Запуск мастера восстановления
1. Откройте оснастку **Certification Authority**.
2. Щелкните правой кнопкой мыши по узлу с именем CA.
3. Выберите **All Tasks** → **Restore CA…** (Все задачи → Восстановить CA).

### Шаг 4.2. Выбор компонентов для восстановления
1. На странице приветствия нажмите **Next**.
2. На странице **Items to Restore** (Элементы для восстановления) выберите:
   - **Certificate database and certificate database log** (База данных сертификатов и журнал базы данных).

### Шаг 4.3. Указание пути к резервной копии
1. Нажмите **Browse**.
2. Перейдите к **родительской папке**, содержащей папку `Database` (например, `C:\CABackup`). **Не выбирайте саму папку `Database`** — выберите папку уровнем выше.
3. Нажмите **Next**, затем **Finish**.
4. На запрос о запуске службы CA ответьте **Yes** (Да).

> 💡 **Примечание:** Если вы восстанавливаете CA на новом сервере после миграции, также потребуется восстановить параметры реестра и список шаблонов сертификатов (для Enterprise CA). Для этого используется импорт файла `.reg`, экспортированного с исходного сервера из ветки `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\CertSvc`.

## 🔬 Задание 5. Восстановление CA с помощью PowerShell

### Шаг 5.1. Запуск PowerShell от имени администратора
Откройте PowerShell с повышенными привилегиями.

### Шаг 5.2. Выполнение восстановления
Используйте командлет `Restore-CARoleService` с параметром `-Path`, указывающим на папку с резервной копией:
```powershell
Restore-CARoleService -Path "C:\CABackup_PS"
```
Этот командлет восстанавливает базу данных CA и информацию о закрытом ключе.

### Шаг 5.3. Восстановление с паролем (если ключ был зашифрован)
Если при резервном копировании использовался пароль, добавьте параметр `-Password`:
```powershell
Restore-CARoleService -Path "C:\CABackup_Secure" -Password (Read-Host -Prompt "Введите пароль" -AsSecureString)
```

> ⚠️ **Важно:** Командлет `Restore-CARoleService` восстанавливает как базу данных, так и закрытый ключ. Убедитесь, что служба `certsvc` остановлена перед восстановлением, если этого требует сценарий.

## 🔬 Задание 6. Восстановление CA с помощью Certutil

### Шаг 6.1. Остановка службы AD CS
Перед восстановлением базы данных остановите службу:
```cmd
net stop certsvc
```

### Шаг 6.2. Восстановление базы данных
Выполните команду:
```cmd
certutil -restoreDB C:\CABackup_CertUtil
```
Параметр `-restoreDB` восстанавливает базу данных из указанной папки.

### Шаг 6.3. Восстановление закрытого ключа и сертификата
Если закрытый ключ и сертификат были сохранены отдельно (через `-backupKey`), восстановите их командой:
```cmd
certutil -restoreKey C:\CABackup_CertUtil
```
Если использовался пароль, добавьте `-p <пароль>`.

### Шаг 6.4. Запуск службы AD CS
После завершения восстановления запустите службу:
```cmd
net start certsvc
```

## ✅ Задание 7. Проверка работоспособности после восстановления

После восстановления CA (любым из способов) выполните следующие проверки:

1. **Убедитесь, что служба AD CS запущена.** В оснастке «Службы» (`services.msc`) служба **Active Directory Certificate Services** должна иметь состояние **Running** (Работает).
2. **Проверьте доступность оснастки CA.** Откройте `certsrv.msc` — узел CA должен отображаться без ошибок.
3. **Проверьте выдачу сертификата.** Запросите тестовый сертификат через веб-интерфейс `https://<CA_Server>/certsrv` или с помощью `certreq`. Убедитесь, что запрос успешно обрабатывается.
4. **Проверьте список отзыва (CRL).** Убедитесь, что CRL доступен и его срок действия не истек.
5. **Сравните базу данных.** Если возможно, проверьте количество выданных сертификатов до и после восстановления (например, через оснастку CA → **Issued Certificates**).
